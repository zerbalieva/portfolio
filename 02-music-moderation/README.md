# Асинхронная система модерации музыкального контента

Проектирование микросервисной системы для отправки музыкального контента на модерацию и обработки результата модерации.

---

## О проекте

Система состоит из двух микросервисов, взаимодействующих асинхронно через Kafka:

- **Moderation Microservice** — принимает запрос от Front, проверяет данные, создаёт заявку на модерацию и отправляет сообщение в Kafka.
- **Response Service** — получает результат модерации из Kafka, обновляет статус заявки и передаёт результат в SMS Service.

---

## Архитектура и взаимодействие

Основное взаимодействие между сервисами происходит асинхронно через Kafka.

### Основной сценарий

1. Front отправляет запрос в Moderation Microservice с `user_id` и `music_id`.
2. Moderation Microservice проверяет входные данные и наличие пользователя и музыкального контента в БД.
3. Создаётся заявка в таблице `moderation_application`.
4. Формируется сообщение для Kafka.
5. Сообщение отправляется в топик `send-music-to-moderation.request`.
6. После завершения модерации Response Service получает результат из топика `send-music-to-moderation.response`.
7. Response Service сопоставляет результат с заявкой по `request_id`.
8. Статус заявки обновляется.
9. Response Service вызывает SMS Service для уведомления пользователя.

---

## Moderation Microservice

- **Назначение:** отправка музыкального контента на модерацию.
- **Протокол:** REST
- **Формат данных:** JSON
- **Безопасность:** HTTPS
- **Тип вызова:** синхронный вызов, асинхронный процесс

### Входные данные

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `user_id` | integer | Идентификатор пользователя |
| `music_id` | integer | Идентификатор музыкального контента |

### Основные проверки

- наличие обязательных атрибутов;
- корректность типов данных;
- наличие пользователя в БД;
- наличие музыкального контента в БД;
- проверка текущего статуса музыкального контента.

---

## Kafka

### Топик: `send-music-to-moderation.request`

Сообщение содержит:

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `music_id` | integer | Идентификатор музыки |
| `user_id` | integer | Идентификатор пользователя |
| `title` | string | Название трека |
| `artist` | string | Исполнитель |
| `file_url` | string | Ссылка на музыкальный файл |

---

## Response Service

- **Назначение:** получение и обработка результата модерации.

Response Service подписан на топик:

`send-music-to-moderation.response`

После получения результата сервис:

- находит заявку по `request_id`;
- обновляет статус заявки;
- вызывает SMS Service;
- при необходимости выполняет повторную отправку уведомления.

---

## База данных

Для хранения информации используется реляционная БД.

### Основные сущности

| Таблица | Описание |
|---------|----------|
| `users` | Пользователи |
| `audio` | Музыкальный контент |
| `moderation_application` | Заявки на модерацию |

### Таблица `moderation_application`

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `request_id` | integer | Уникальный идентификатор заявки |
| `user_id` | integer | Идентификатор пользователя |
| `music_id` | integer | Идентификатор музыкального контента |
| `request_status` | string | Статус заявки |
| `created_at` | datetime | Дата и время создания |
| `request_payload` | JSONB | JSON-сообщение в Kafka |
| `user_notified` | boolean | Проверка отправки уведомления |
